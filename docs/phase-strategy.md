# 开局 / 中局 / 残局：策略调整一览

本文单独整理引擎在**不同阶段**对评估、着法排序、搜索预算与开局库的差异。  
实现主要在 `engine/book.py`、`engine/evaluate.py`、`engine/search.py`、`engine/decide.py`（native 核 `ext/*.pxi` 与之同步）。

详细算法见 [decision-logic.md](decision-logic.md)；识别侧开局/中局门控见 [recognize-logic.md](recognize-logic.md)。

---

## 0. 阶段如何判定

引擎**没有**显式的「中局」枚举，实际是两套门控叠加：

| 门控 | 条件 | 用途 |
|------|------|------|
| **开局** `Board.is_opening()` | `piece_count > 26` **且** 双方将帅仍在原位（红帅 sq85、黑将 sq4） | 评估出子/深入/炮兵线；搜索开局吃子降权 |
| **残局加深** `endgame_search_budget()` | 仅看 `piece_count`：≤20 / ≤16 / ≤12 | 提高迭代深度与时间预算 |
| **中局**（默认） | 非开局，且未触发残局加深（或已加深但评估仍走通用 PST） | 子力+PST+控线为主，无开局专项 |

示意：

```text
子力多 + 将帅原位 ──► 开局策略（库 / 出子 / 反贪打兵 / 深入惩罚）
        │ 将帅离位或子力 ≤26
        ▼
   通用中局搜索评估 ◄── 默认
        │ piece_count ≤ 20
        ▼
   残局：加深搜索（评估不再扣「深入」）
```

---

## 1. 开局

### 1.1 目标

浅层搜索看不清布局后果 → **先跟经典主线**，脱谱后再搜；并抑制「炮打兵、大子乱入底线」等贪吃。

### 1.2 开局库（`engine/book.py`）

- 3 条经典主线，各约 **3–5 回合**（半步写入局面表）：
  - **中炮对屏风马**（权重 100）
  - **中炮对顺炮**（95）
  - **仙人指路对卒底炮**（85）
- 起手次选：炮八平五 / 黑先镜像炮2平5。
- 黑先走（截图「我方在下」）：主线上下镜像，同一套布局意图。
- **命中**：第 1 手用库；分析路径 `fill_pv=True` 时对后续局面再 `search` 补满推演；对弈可不续搜。
- **对方偏离**：脱库 → 交还普通搜索（仍可能处在 `is_opening()` 评估/排序门控内）。

### 1.3 评估（仅 `is_opening()` 时）

| 项 | 行为 |
|----|------|
| 深入惩罚 `_DEEP` | 车/马/炮进入对方底三行按子力约 20% 扣分（**只在开局叠加**；已不进 `base_score`） |
| 出子 | 马离原位、己方半场中炮/肋道炮、兵挺起、车离开底线等加分 |
| 炮入对方兵线 | **−80**（抑制开局炮打兵落点）；中炮/肋炮加分**仅计己方半场** |
| 士象 | 仍计防守分；缺仕/缺相惩罚 |

残局/中局**不再**扣深入，避免大子攻将时被错误压分。

### 1.4 着法排序（仅开局）

在 MVV-LVA + SEE 之上额外降权：

| 情况 | 降权（约） |
|------|------------|
| 炮吃子且落入对方底三行 | −60000 |
| 马/车吃子且落入对方底三行 | −40000 |
| 炮吃兵（兵线不在底三行，单独一条） | −55000 |
| 马/车吃兵 | −35000 |

目的：优先展开出子、布局着，而不是「炮打中卒」一类贪吃。

### 1.5 SEE（全阶段，开局尤其受益）

落点可被对方吃回 → 扣**满**攻击子价值（不再 `attacker/4` 假阳性）。  
开局「车换马/炮、炮打有根兵」更不容易在排序里看起来像赚。

## 2. 中局

### 2.1 目标

脱开开局专项后，以**子力 + PST + 车炮控线 + 士象**为主；靠搜索深度与静搜处理战术。

### 2.2 评估

- `base_score`：子力 + PST（无深入项）。
- 扫盘：控线、仕相完整度；**无**开局出子/深入/炮兵线惩罚。
- PST 全阶段共用一张表（已知局限：无开/中/残切换）。

### 2.3 搜索

- 标准 Negamax + 静搜吃子、TT、空着、LMR、aspiration。
- **无**开局吃子降权；吃子仍按 MVV-LVA + 一层 SEE。
- 分析页 `top_n>0`：分差 &lt; 50 厘兵时软偏好**安静着**优于吃子；对弈 `top_n=0` 关闭。

### 2.4 与开局的边界

一旦将帅离位或总子数 ≤26，即退出开局门控；即使仍「看起来像开局」，也不再给开局库以外的开局评估/降权（库仅匹配具体 FEN）。

---

## 3. 残局

### 3.1 目标

子少后战术空间变大、杀棋更远 → **自动加深**；评估上允许大子深入，避免为兑子而乱换。

### 3.2 搜索预算（`decide.endgame_search_budget`）

| `piece_count` | 深度加成 | 时间 |
|---------------|----------|------|
| ≤ 20 | +1 | ×2 |
| ≤ 16 | +2 | ×4 |
| ≤ 12 | +3 | ×8 |

深度封顶 **12**，时间封顶 **90s**。分析页与对弈页均在 `decide_position` 入口生效。

### 3.3 评估与兑子

- **不扣**开局深入惩罚 → 车马炮压境攻将分正常。
- SEE：有根则扣满攻击子 → 抑制「大优时车换马/炮」。
- 无显式「占优拒兑」项；主要靠正确子力差 + 加深搜索。

### 3.4 其它

- 重复局面仍记和（0）：大优时长将/长捉可能偏乐观（见 decision-logic 已知局限）。
- 识别侧残局不依赖开局底线种子（另文）。

## 4. 对照总表

| 策略项 | 开局 | 中局 | 残局 |
|--------|------|------|------|
| 经典开局库 | 有（前 3–5 回合） | 仅当 FEN 仍命中 | 同左（少见） |
| 出子 / 中炮半场加分 | 有 | 无 | 无 |
| 深入底线惩罚 | 有 | 无 | 无 |
| 炮入兵线 −80 | 有 | 无 | 无 |
| 吃兵 / 深入吃子排序降权 | 有 | 无 | 无 |
| SEE 有根扣满攻击子 | 有 | 有 | 有 |
| 自动加深搜索 | 无 | 子数≤20 起 | 加强 |
| 软偏好安静着 | 分析页可 | 同左 | 同左 |

---

## 5. 改阶段策略时注意

1. **Python 与 `ext/*.pxi` 必须同步**，改完 `python setup.py build_ext --inplace`，并重启 UI。  
2. 开局库只定第 1 手时，分析路径须续搜补 PV（防回退契约）。  
3. 回归：`python -m unittest test.test_xiangqi_engine -v`（含开局库、SEE、开局反打兵、残局相关用例）。  
4. 识别「近开局 / 中局」门控与棋力阶段独立，勿混改。
